# 分层提示词

> 依据：架构书 二(四) 提示词工程策略、SPEC-01 §3 目录结构规范

智能体的行为质量主要由提示词决定。本项目采用**分层提示词架构**，四层各占一个目录。

| 子目录 | 对应架构书层次 | 内容 |
| --- | --- | --- |
| `role/` | 角色层 | 身份、专业边界、能力声明 —— 定义智能体是谁、能做什么、不能做什么 |
| `principle/` | 原则层 | 探讨式引导、承认知识边界、可溯源、学术诚信 —— 跨场景的恒定约束 |
| `task/` | 任务层 | 各子智能体的具体工作流与输出格式 —— 因任务而异 |
| `context/` | 上下文层 | 用户画像、当前研究方向、历史交互摘要 —— 由长期记忆动态注入 |

## 命名规则

`<层次>-<对象>.md`，例如 `role-主控智能体.md`、`task-前沿雷达.md`、`principle-通用约束.md`。

## 开发流程

架构书二(四)规定：**本地起草 → 平台验证 → 版本留痕**

| 环节 | 落地方式 |
| --- | --- |
| 本地起草 | 在本目录编写，front matter 中 `status: draft` |
| 平台验证 | 在 LearnBuddy 上实测，记录 `platform_validated_at`，`status` 改为 `verified` |
| 版本留痕 | front matter 的 `迭代说明` 表格逐版记录变更与验证结果 |

## 硬性要求

1. 每个文件**必须**有 front matter（字段见 SPEC-02 §3.4）。
2. 版本变更时**必须**同步更新 `version` 与 `迭代说明`表格。
3. 提交时使用 `prompt(<scope>)` 类型，便于统计提示词迭代轮次。
4. 相关 AI 使用过程须归档 `iteration-log/`。
