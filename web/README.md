# Web 展示层

> 依据：架构书 四(二) Web 入口、四(三) 展示形态的选择依据、五(二) Web 侧技术栈

## 定位

**只读展示加跳转入口的极简定位，不实现独立的智能体逻辑。**
（架构书四(二)原文）

## 为什么需要 Web 层

架构书四(三)说明：对话交互、记忆、检索、多智能体协作均由平台原生承载；
而**图形化表达**（路线图、依赖关系、简报聚合）恰恰是平台对话界面不擅长、Web 页面擅长的部分。
两者互补而非重叠。

## 技术栈（架构书五(二)锁定）

| 类别 | 选型 |
| --- | --- |
| 页面技术 | HTML + CSS + 原生 JavaScript，单页形态，不引入重型框架 |
| 图表可视化 | ECharts |
| 图谱可视化 | 轻量图可视化方案（基于 SVG 自绘或成熟图库） |
| 数据源 | 静态 JSON 数据文件（读 `data/`） |
| 构建 | **无需构建工具**，直接浏览器打开 `index.html` 可预览 |

## 页面规划

| 页面 | 内容 | 数据来源 |
| --- | --- | --- |
| 首页 | 项目介绍、核心能力概览、智能体体验入口跳转 | 静态内容 |
| 学习路线 | 路线图可视化、知识点依赖关系、阶段进度 | `data/route/` |
| 前沿简报 | 每日简报列表、按方向筛选、关联度标注 | `data/briefing/` |
| 知识资产 | 已沉淀知识条目总览、检索、导出 | `data/assets/` |

## 硬性约束

| 约束 | 依据 |
| --- | --- |
| 不引入重型 SPA 框架 | 架构书五(三)明确排除 |
| 不调用大模型 API | 架构书五(三)明确排除 |
| 不建后端服务与数据库 | 架构书五(三)明确排除 |
| **所有条目均标注出处链接** | 架构书四(二)要求 |
| 只消费 `data/`，不读 `knowledge/` | SPEC-01 §3 单向依赖 |
