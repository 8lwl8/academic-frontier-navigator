# AI 使用留痕

> 依据：SPEC-03 §6.3、SPEC-04 §6、赛事手册 8.3

## 为什么这个目录存在

架构书六(二)要求：**「AI 使用边界：严格遵守手册 8.3，AI 用于提效而非替代，保留完整迭代记录以备评审。」**

赛事把「AI 工具使用」单列 **25% 分值**，本目录就是该分值的直接举证材料。

## 记录规则

| 规则 | 说明 |
| --- | --- |
| **命名** | `YYYY-MM-DD-<主题>.md` |
| **粒度** | 一轮完整迭代一份 |
| **归档时限** | 迭代结束后 **24 小时内** |
| **只增不删** | 归档后不得修改、删除、重写。补充内容用追加段落 |
| **不做美化** | 不要事后把提示词润色得像模板，真实过程才有说服力 |

## 必含内容

| 节 | 为什么必须 |
| --- | --- |
| 元信息（时间、执行人、AI 工具、会话标识） | 证明记录真实性 |
| 迭代目的 | 证明是有目标的使用，非盲目尝试 |
| **原始提示词全文** | **核心证据**，展示提问质量 |
| **AI 关键输出摘录** | 展示协作过程 |
| **人工调整说明** | **证明「提效非替代」的关键** |
| 失败尝试记录 | **失败记录比成功记录更能证明使用深度** |
| 结论与产物 | 建立与提交记录的关联 |

## 关于「人工调整说明」

只写「AI 生成了 X，然后就是 X」反而说明使用深度不足。

真正有说服力的记录是：

> 「AI 生成了 X，但 X 在 Y 场景下会出错（附具体表现），我改为 Z，理由是……」

这体现的是人对 AI 输出的判断与驾驭，而不是把工作外包。

## 使用方式

复制 `templates/iteration-log.template.md` 到本目录，按格式填写。
