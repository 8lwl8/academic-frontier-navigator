# 第三方资源清单

> 依据：SPEC-04 §5 第三方资源登记、架构书 六(二)「**知识产权**：使用的第三方库与开源资源在文档中注明；作品按开源协议发布」
>
> **登记规则**：引入任何第三方资源（库、框架、数据集、素材）都必须在此登记一行。未登记的资源不得引入。
>
> **许可证兼容性红线**：本项目采用 MIT 发布，引入的资源须为 MIT / Apache-2.0 / BSD 等宽松许可。**禁止引入 GPL / AGPL 类传染性许可的库** —— 会与 MIT 开源发布产生冲突。

## 三、明确不引入的资源

> 依据架构书 五(三) 明确排除的选型，以下类别**不得**引入本项目。

| 排除项 | 理由（架构书原文） |
| --- | --- |
| 重型前端框架（大型 SPA 框架） | Web 侧仅为只读展示，引入框架的收益低于其学习与调试成本 |
| 自建后端服务与数据库 | 用户数据与知识资产由平台承载，自建将带来额外的部署与运维负担 |
| Web 侧独立调用大模型 API | 造成能力分散与算力重复消耗，且无法复用平台的记忆与知识库 |
| 微服务、容器编排等基础设施方案 | 与 10 天周期和轻量交付目标严重不匹配 |
| 生产级监控、CI/CD 流水线 | 初赛只需演示与在线可访问，不投入生产化建设 |

## 四、新增资源的登记流程

1. **确认必要性** —— 是否属于架构书五(三)的排除项？若是，重新评估需求。
2. **确认许可证** —— 是否为 MIT / Apache-2.0 / BSD 等宽松许可？GPL / AGPL 一律不引入。
3. **在本文件追加一行** —— 填写名称、版本、许可证、用途、是否修改、出处。
4. **同步 `CHANGELOG.md`** —— 在 `[未发布]` 的「新增」段落记一行。
