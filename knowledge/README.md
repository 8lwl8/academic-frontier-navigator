# 知识库

> 依据：架构书 三(四) 知识库设计、SPEC-01 §3 目录结构规范

知识库是全部智能体能力的共同地基，采用**分库结构**。三库**不得混放**。

| 子库 | 内容来源（架构书原文） | 服务对象 | 文件格式 |
| --- | --- | --- | --- |
| `domains/` | 顶会论文、经典教材、综述文章、公开课材料、开源项目文档 | 路线规划、论文精读 | Markdown 知识单元 |
| `intelligence/` | 每日抓取的论文与项目动态 | 前沿雷达 | JSON 结构化简报 |
| `personal/` | 用户阅读笔记、对话结论、学习轨迹 | 知识管家 | Markdown |

## 知识组织方式

按「**领域 → 子方向 → 知识点 → 文献**」的层级组织，并标注知识点之间的依赖关系。
该依赖结构是学习路线生成的依据，也是本项目知识库设计相比普通文档库的核心差异。

## 语料准入标准

来源**可公开访问**、有**明确作者与出处**、属于该领域的**奠基性或代表性成果**、**时效性**满足要求。
低质量或来源不明的语料不入库。

## 硬性要求

1. `domains/` 下每个知识单元的 front matter **必须**含 `source` 对象，且 `source.url` 真实可访问。
2. 知识单元的 `id` 全库唯一，格式 `kn-NNNN`。
3. `prerequisites` 不得出现循环依赖。
4. `personal/` 下**只提交脱敏样例**（`*.example.md`），真实个人数据不入库。

格式详见 [SPEC-02 格式约定](../../docs/spec/02-格式约定.md) §3.2。
