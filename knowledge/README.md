# 知识库

> **规范正文见 [`docs/spec/06-knowledge-base-and-corpus-admission.md`](../docs/spec/06-knowledge-base-and-corpus-admission.md)（SPEC-06）。**
> 本文件是入口索引，规范条款以 SPEC-06 为准。

知识库是全部智能体能力的共同地基，采用**分库结构**。三库**不得混放**。

| 子库 | 内容来源（架构书原文） | 服务对象 | 文件格式 | 敏感级别 |
| --- | --- | --- | --- | --- |
| [`domains/`](domains/) | 顶会论文、经典教材、综述文章、公开课材料、开源项目文档 | 路线规划、论文精读 | Markdown 知识单元 | 低 · 公开 |
| [`intelligence/`](intelligence/) | 每日抓取的论文与项目动态 | 前沿雷达 | JSON 结构化简报 + Markdown 说明 | 低 · 公开 |
| [`personal/`](personal/) | 用户阅读笔记、对话结论、学习轨迹 | 知识管家 | Markdown | 中 · **默认私密** |

---

## 一、三分库判据（SPEC-06 §三）

一条语料进来，先回答三个问题，任一得到明确答案即停止：

1. **它是「领域公认的知识」还是「最近发生的事」？** → 公认知识走 `domains/`；最近的事走 `intelligence/` 或 `personal/`。
2. **它的价值归属于「所有人」还是「某个用户」？** → 所有人走 `domains/`/`intelligence/`；某用户走 `personal/`。
3. **它是「原材料」还是「加工产物」？** → 原材料进 `domains/`；加工产物按加工者：智能体加工的进 `intelligence/`，用户加工的进 `personal/`。

### ⚠️ 三库不得混放，也不得搬运

跨库流动必须经过**重新提炼**，不得直接复制（SPEC-06 §2.3）：

| 流动 | 允许 | 不允许 |
| --- | --- | --- |
| 情报 → 领域 | ✅ 经时间检验后重新提炼为知识单元 | ❌ 直接复制情报条目 |
| 情报 → 个人 | ✅ 精读后形成笔记 | ❌ 原样存为资产 |
| 领域 → 个人 | ✅ 学习后产生的理解 | ❌ 复制知识单元原文 |

> **最常见的错误**：把某天抓到的新论文写进 `domains/`，导致路线规划智能体把它当作必读经典推荐。

## 二、知识组织方式（SPEC-06 §四）

按「**领域 → 子方向 → 知识点 → 文献**」四层组织，并标注知识点之间的依赖关系。

这四层不是四个文件夹，而是**同一条知识单元上的四个坐标** —— 前三层由 front matter 的 `domain` / `sub_domain` / `knowledge_point` 承载，第四层由 `source` 承载。

| 层级 | 数量约束 | 对应字段 |
| --- | --- | --- |
| L1 领域 | 全库 **1–2 个** | `domain` |
| L2 子方向 | 每个领域 **3–6 个** | `sub_domain`（须先在 `_index.md` 登记） |
| L3 知识点 | 每个子方向 **3–10 个** | `knowledge_point` + `id` |
| L4 文献 | 每条知识点 **1–n 篇** | `source`（`url` 必填） |

**依赖关系**是本研究相对普通文档库的核心差异（架构书三(四)、八章），建模规则详见 SPEC-06 §五：

- 边方向：**前置 → 后继**（`B.prerequisites` 中写 `A`）
- 三种关系：`prerequisite_of`（影响学习顺序）/ `related_to`（仅用于图谱展示）/ `extends`（可选的深入方向）
- **严禁循环依赖** —— 会直接摧毁路线生成能力，由脚本强制拦截

## 三、语料准入标准（SPEC-06 §六）

架构书三(四)给出四项标准，SPEC-06 将其细化为**四维量表**，**一票否决制**（不做加权平均）：

| 维度 | 判定问题 | 最低要求 |
| --- | --- | --- |
| **A 可访问性** | 匿名窗口能否打开？ | ✅ 返回 200，无登录墙、无付费墙 |
| **B 出处明确** | 作者是谁？是原始文献吗？ | ✅ 作者 + 出处 + 年份齐全 |
| **C 权威性** | 在该子方向地位如何？ | ✅ C1 奠基性 / C2 代表性 / C4 参考性 |
| **D 时效性** | 是否过时或被推翻？ | ✅ 按库分别判定（见下） |

**各库时效阈值**：`domains/` 无硬性年限但需通过「三年后是否成立」检验，每 6 个月复核；`intelligence/` 抓取窗口 7 天；`personal/` 无年限要求。

> **C 维度的一票否决是硬红线**：来源不明、AI 生成未标注、营销内容一律拒绝，**无例外**（SPEC-04 §3.3：让 AI 编造文献信息属严重违规）。

## 四、出处核验的强制流程（SPEC-06 §6.5）

SPEC-04 §3.3：「`knowledge/domains/` 下每个知识单元的 `source` 字段，**必须由人工逐一访问 `url` 确认可达且内容匹配**。这条规则没有例外。」

```text
① 匿名窗口打开 source.url        → 返回 200 且标题与 source.title 一致
② 核对作者与年份                  → 与 source.authors / published_date 一致
③ 确认内容支撑该知识点             → 非张冠李戴
④ 在 iteration-log 记录核验时间与人
```

> **为什么必须用匿名窗口**：登录态下可访问的链接，评审访问时可能 403。**只以匿名态为准。**

## 五、复核与退出（SPEC-06 §七）

知识库需能**撤回**已入库的语料，否则会持续劣化。

| 触发情形 | 处理时限 | 处置方式 |
| --- | --- | --- |
| 距上次复核满 6 个月 | 3 日内 | 更新 / 降级 / 下线 |
| `source.url` 失效 | 立即 | 优先**更新**链接；无法恢复则**下线** |
| 结论被新成果推翻 | 1 周内 | **降级**（保留并标注局限）或**下线** |

> **`id` 永不复用**（与 ADR 编号规则同理）：即使 `kn-0007` 被下线，新知识点也用下一个未用号。复用会让历史引用指向错误内容。

---

## 六、硬性要求（提交前检查）

1. `domains/` 下每个知识单元的 front matter **必须**含 `source` 对象，且 `source.url` 真实可访问。
2. 知识单元的 `id` 全库唯一，格式 `kn-NNNN`，**永不复用**。
3. `prerequisites` 不得出现循环依赖，不得悬空引用，不得自环。
4. `sub_domain` 取值必须已在 `domains/_index.md` 中登记。
5. `personal/` 下**只提交脱敏样例**（`*.example.md`），真实个人数据不入库。
6. `data/briefing/` 与 `data/assets/` 由 `scripts/` 生成，**禁止手工编辑**。

### 校验命令

```bash
# 校验知识单元结构、字段、依赖图（无环、无悬空、无自环）
python scripts/check_knowledge_units.py

# 额外核验全部 source.url 可达性（需联网）
python scripts/check_knowledge_units.py --url-check

# 校验 data/ 下的 JSON 是否符合 Schema 契约
python scripts/validate_schemas.py
```

格式详见 [SPEC-02 格式约定](../../docs/spec/02-格式约定.md) §3.2；分库与准入详见 [SPEC-06](../../docs/spec/06-knowledge-base-and-corpus-admission.md)。
