# 个人资产库 · 脱敏样例

> 依据：SPEC-06 §3.4 分库判据、SPEC-02 §7 数据分类与可见度、架构书 六(一)(二)
> 服务对象：**知识管家智能体**（架构书三(四)）
> 写入方：`asset-extract` Skill（架构书三(一)）
> 数据契约：`schemas/asset.schema.json`

---

## ⚠️ 请先读这一节

**本目录在公开仓库中只存放脱敏样例，真实个人数据一律不入库。**

| 规则 | 说明 |
| --- | --- |
| 文件名 | 样例以 `.example.md` 结尾；真实文件以 `.private.md` 结尾 |
| `.gitignore` | 已按 `knowledge/personal/**/*.private.*` 模式屏蔽真实数据 |
| 敏感级别 | 架构书六(1) 将「用户画像与学习轨迹」「个人知识资产」归为**中**敏感级 |
| 默认可见度 | `private`（架构书六(2)：**默认私密**） |

> 为什么这么严：用户画像与学习轨迹若泄露，暴露的是具体个人的研究兴趣与能力短板。仓库是公开的，一旦提交即便后续删除，Git 历史中仍然存在。

---

## 一、本库沉淀什么

架构书三(3)规定：「**只沉淀有长期价值的结构化信息，不记录原始对话流水**（原始记录由对话历史承担），避免记忆污染。」

| 沉淀（✅） | 不沉淀（❌） |
| --- | --- |
| 结构化结论（「两种损失函数的适用边界」） | 30 轮完整对话记录 |
| 进度结构化（「已完成 3 个知识点，卡在 X」） | 「用户今天问了什么」的流水账 |
| 偏好结构化（「偏好先看代码再看公式」） | 原始交互文本 |
| 文献卡片（研究问题/方法/创新点/局限） | 论文全文 |

> **记忆的价值来自筛选，不来自堆积。** 全量沉淀会降低知识管家的检索精度 —— 噪声命中比无命中更糟，因为它会诱使智能体给出看似有据实则无关的回答。

## 二、四类记忆分层（架构书三(三)）

| 记忆类型 | 内容 | 更新时机 | 用途 |
| --- | --- | --- | --- |
| **用户画像** | 专业背景、已掌握知识、研究方向、学习目标 | 首次使用 + 显著变化时 | 决定输出的深度与假设前提 |
| **进度记忆** | 当前学习阶段、已完成任务、卡点 | 每次学习行为后 | 支撑路线动态调整 |
| **偏好记忆** | 交互风格偏好、关注的论文类型、简报密度偏好 | 持续累积 | 提升个性化程度 |
| **项目轨迹** | 长期科研任务的上下文与进展 | 任务推进时 | 支撑跨会话的连贯指导 |

## 三、脱敏样例：一条文献卡片资产

以下为一条**完全虚构**的脱敏样例，用于说明字段填法。所有人名、机构、方向均为示意。

```json
{
  "schema_version": "1.0",
  "asset_id": "asset-0001",
  "type": "literature_card",
  "title": "某序列建模方法的精读卡片",
  "summary": "该工作把全局注意力替换为局部窗口加少量全局标记，在长序列上降低计算量的同时保留了长距离信息通路。",
  "content_path": "knowledge/personal/litcard-example.example.md",
  "tags": ["序列建模", "注意力", "长上下文"],
  "origin": {
    "kind": "reading",
    "ref": "session-2026-09-18-01",
    "extracted_by": "asset-extract@v1.0"
  },
  "visibility": "private",
  "created_at": "2026-09-18",
  "updated_at": "2026-09-18"
}
```

**字段说明**：

| 字段 | 为什么这么填 |
| --- | --- |
| `visibility` | 取 `private`，对应架构书六(2)「默认私密」。即使在样例中也不写成 `public`，避免误导 |
| `origin.kind` | 取 `reading`（枚举为 `conversation` / `reading` / `manual`），说明来自阅读而非对话 |
| `origin.ref` | 指向会话标识，使资产可溯源到具体一次学习行为 |
| `type` | 取 `literature_card`（枚举为 `note` / `summary` / `route_snapshot` / `literature_card`） |
| `summary` | 200 字以内，是可复用的结论而非原文摘录 |

## 四、脱敏要求

| 项 | 要求 |
| --- | --- |
| 姓名 | 用「某同学」「用户 A」替代 |
| 学校/院系 | 不出现具体机构名 |
| 学号/联系方式 | **绝不出现** |
| 研究方向 | 可保留（这是资产价值所在），但样例中应虚构 |
| 会话标识 | 可保留（用于溯源），但不得包含可反查个人的信息 |

## 五、准入与退出（SPEC-06 §6.4(三)、§七）

| 检查项 | 要求 |
| --- | --- |
| 结构化程度 | ✅ 已提炼为结论，非原始流水 |
| `visibility` | ✅ 默认 `private` |
| `origin` 可溯源 | ✅ 记录来源类型与 `ref` |
| **脱敏** | ✅ 仓库内只提交 `*.example.*` |
| 不侵犯原文版权 | ✅ 引用与转述，不搬运全文 |

**退出机制**：用户可删除任意资产。删除时须同步清理 `data/assets/` 中的对应条目与 `content_path` 指向的正文文件，避免留下悬空引用。
