# 自研 Skills

> 依据：架构书 三(一) Skills 组件规划

自研 Skills 是本项目的**技术亮点之一**，也是「技术创新性」评分的支撑点。

## 规划的四类自研 Skills

| Skill 目录 | 职责（架构书原文） |
| --- | --- |
| `paper-deep-read/` | 输入一篇论文，输出结构化精读卡：研究问题、方法思路、创新点、局限、与用户方向的关联 |
| `route-generate/` | 输入方向与基础，输出分阶段路线与知识点依赖顺序 |
| `briefing-generate/` | 输入检索结果集与用户画像，输出按相关性排序的简报 |
| `asset-extract/` | 输入对话记录，输出结构化知识条目并写入知识库 |

## 硬性要求

架构书三(一)规定：「**每个 Skills 须有明确的输入契约、输出格式与失败处理策略。**」

因此每个 Skill 目录下的 `README.md` **必须**包含三节：

| 节 | 内容 | 检查点 |
| --- | --- | --- |
| 输入契约 | 参数名、类型、必填性、取值范围 | 与调用方约定一致 |
| 输出格式 | 结构示例 + 对应 JSON Schema 路径 | Schema 文件真实存在 |
| 失败处理 | 各类失败场景的降级行为 | 符合架构书三(二)「不阻塞用户其他操作」 |

缺失任一节视为未完成。

## 目录结构

```text
skills/<skill-name>/
├── README.md       # 必含三节
├── skill.py        # 实现（Python）
└── samples/        # 示例输入输出
```

## 设计原则

架构书七(三)指出：自研 Skills 采用**可插拔设计**，新增能力只需增加 Skills 组件，
主控智能体的路由表扩展即可。因此：

- 每个 Skill 独立目录，不互相依赖；
- 输入输出以 JSON 为契约，不传内部对象；
- 失败时不抛异常阻塞上层，而是返回降级结果并记录。
